# Основания правил экономии токенов

Дата проверки источников: 2026-10-11. Эта справка предназначена для сопровождения шаблона. Агенту не требуется читать её для каждой задачи.

Рекомендации ниже перенесены в шаблон как условия работы. Это наша адаптация первичных источников, а не измерение экономии в Codex. Универсальный процент экономии не установлен.

## Что добавлено

| Рекомендация | Применение в шаблоне |
| --- | --- |
| Точные подсчёты и преобразования выполнять доступными инструментами | `context.md`: подсчёт, сравнение и фильтрация без чтения моделью всего набора |
| Промежуточные данные обрабатывать до передачи в контекст | `context.md`: возвращать итог и доказательства, сохранять доступ к нужным исходным данным |
| Объединять необходимые запросы, когда это уместно | `context.md`: только независимые чтения, отдельные результаты и ошибки, прежняя область данных |
| Загружать описания инструментов по необходимости | `context.md`: при наличии поиска инструментов выбирать описания по операции |
| Сохранять краткое состояние для длинной работы | `task-and-contract.md`: ограничения, решения, неудачные попытки, артефакты, доказательства и оставшаяся работа |

Обычные средства обработки могут заменить ненужный вызов модели. Несколько запросов иногда можно объединить. Это уменьшает число обращений, но само по себе не доказывает уменьшение общего расхода токенов. [OpenAI: Latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization).

Обработка результатов в среде инструмента позволяет передавать модели только нужную часть данных. Описания инструментов можно обнаруживать по необходимости, если среда предоставляет такую возможность. Шаблон не требует создавать MCP-сервер или устанавливать новый исполнитель ради этих приёмов. [Anthropic: Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp).

Краткое состояние помогает продолжать длительную задачу после сокращения контекста. Оно должно сохранять существенные решения и нерешённые вопросы. Слишком сильное сокращение может потерять важные условия. Шаблон использует один существующий источник состояния и не требует отдельной заметки после каждого действия. [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).

## Что уже было

- Чтение по условиям задачи, ограниченные выборки и точный поиск.
- Краткий вывод с сохранением ошибок и доказательств.
- Минимальные правки и использование принятых проверок текущей версии.
- Подбор модели и бюджета в роутере, управление исполнителями в менеджере.
- Одна ретроспектива общего результата вместо повторного исследования.

Фильтрация, выбор диапазонов и понятные ошибки инструментов поддерживают выборочное чтение. Эти требования уже есть в `context.md` и `verification.md`; второй набор правил не добавлен. [Anthropic: Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents).

## Что не стало обязательным правилом

- **Кэширование.** Совпадение префикса и настройки запросов влияют на повторное использование кэша. Кэш уменьшает применимую стоимость входа, но не удаляет токены из запроса. Его настройкой может управлять клиент, а не агент проекта. Сохраняйте неизменные инструкции стабильными там, где это уместно. Исправляйте их при изменении требований. Не добавляйте текст ради порога кэша без оценки полного расхода. [OpenAI: Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).
- **Обязательное распараллеливание.** Оно может уменьшить время, но требует учёта общей стоимости. Решение остаётся в роутере и менеджере.
- **Самая дешёвая модель для любой работы.** Нужны достаточное качество и оценка затрат до приёмки. Это уже задача роутера.
- **Жёсткий лимит длины любого ответа или журнала.** Он может скрыть требование, ошибку или часть артефакта. Шаблон ограничивает область вывода по вопросу и сохраняет доказательства.
- **Обязательные новые системы памяти, fine-tuning или API Batch.** Это отдельные возможности конкретной среды, а не необходимые зависимости универсального проекта.

## Проверка применимости

| Ситуация | Ожидаемый результат |
| --- | --- |
| Подсчёт строк или суммы в таблице | Доступный инструмент вычисляет точный результат; модель получает итог и нужную проверку |
| Чтение двух независимых источников | Можно объединить запросы; ошибка одного источника остаётся видимой |
| Второй запрос зависит от первого | Запросы выполняются последовательно |
| Короткая правка текста | Не создаются система памяти, новые инструменты или отдельный журнал состояния |
| Продолжение после сокращения контекста | Используется краткое состояние; меняющиеся факты проверяются при необходимости |
| Работа с графикой | Состояние содержит путь к текущему исходнику и критерии; визуальные проверки сохраняются |

Точный эффект можно оценить только по сопоставимым задачам и доступным счётчикам. Сокращение времени, токенов и денежной стоимости — разные показатели.
