# Проверки и приёмка

- До запуска определи вопрос, команду или действие и критерий успеха.
  Используй существующую проверку. Не угадывай её параметры.
  Если проверки ещё нет, выбери минимальный способ по критериям приёмки.
- Начни с затронутой области и существенных зависимостей.
  После интеграции выполни необходимую общую проверку.
  Не запускай все проверки после каждой малой правки без связи с её последствиями.
  Используй принятую проверку другого агента для той же версии и условий.
  Само получение результата не требует повторного запуска. Проверяй конкретные пробелы, изменения или противоречия.
- Делай вывод успешных проверок кратким: имя проверки и результат.
  Для команды сохраняй код завершения.
  Полный stdout и stderr при необходимости сохраняй в локальный журнал.
- При ошибке покажи имя проверки, код завершения, полезный фрагмент причины и ссылку на имеющееся доказательство или журнал.
  Не повторяй запуск только для создания файла журнала, если причина и статус уже получены.
  Добавляй детали по вопросу диагностики или запросу пользователя.
  Не скрывай отказ через `|| true`, перенаправление в `/dev/null` или обрезку, которая теряет статус процесса.
- До создания тихого запуска проверь штатный quiet-режим или runner проекта.
  Не создавай новую обёртку для каждого теста.
- После ошибки выясни причину. Не повторяй одинаковый запуск без изменения условий или подтверждения временного сбоя.
- Повторяй проверку после изменения её входа, результата, существенной зависимости или при пробеле в доказательствах.
  Используй прежние доказательства для неизменённых элементов.
- Принимай результат по критериям и доказательствам текущей версии.
  Для неподтверждённого пункта укажи ограничение.
  Заверши работу кратким отчётом: результат, проверка и существенные отклонения.
