# Задача и договор о результате

- Соблюдай инструкции среды, ограничения пользователя и правила проекта.
- До работы определи цель, результат, границы, исходные данные и критерии приёмки.
  Используй текущий запрос или существующее задание. Не создавай отдельный документ для простой задачи.
- Если задача зависит от технологии, установи фактический стек и версии по конфигурации проекта.
  Найди документированный запуск и ближайшую проверку. Не выбирай новый стек по привычке.
  Для задачи без такой зависимости не исследуй стек.
- Для общего интерфейса или результата зафиксируй вход, выход, ограничения, владельца и потребителей.
  Для артефакта укажи нужные формат, единицы, структуру и источник истины.
  Используй существующее задание или договор. Создай отдельный контракт только для устойчивого общего интерфейса, если текущего задания недостаточно.
- Перед изменением контракта найди затронутых потребителей и проверки.
  Отделяй действующие требования от будущих предложений.
- При существенном противоречии уточни требования. Продолжай независимую работу.
- Выбери минимальный достаточный объём результата и подходящий способ проверки.
  Для неизвестного решения сначала проверь небольшой образец или гипотезу.
- Главный агент сохраняет ответственность за интеграцию и итоговую приёмку.
  Для продолжительной задачи веди один краткий источник состояния: решения, завершённые части, доказательства и оставшаяся работа.
  Сохраняй также существенные ограничения, причины неудачных попыток и ссылки на текущие артефакты. Обновляй состояние при существенных изменениях.
  После сокращения контекста продолжай из этого состояния. Не восстанавливай всю историю заново.
  При пробеле или противоречии проверь только нужный текущий источник. Не считай сохранённую запись доказательством актуальности изменяемых данных.
