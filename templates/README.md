# Универсальный шаблон правил проекта

[Шаблон](universal-project/AGENTS.md) подходит для кода, документов, исследований, данных и графики. Корневой `AGENTS.md` содержит маршрут к восьми профилям в `agent-rules/`. Агент читает профили по условиям задачи. Профиль не запускает отдельного субагента автоматически.

Главный агент определяет результат, границы и критерии приёмки. Он выбирает работу самостоятельно или через исполнителей. Он отвечает за общие контракты, интеграцию и окончательную приёмку.

## Состав

| Файл | Назначение |
| --- | --- |
| `AGENTS.md` | Условия чтения профилей |
| `agent-rules/task-and-contract.md` | Результат, дорожная карта, режим разрешений и контракты |
| `agent-rules/context.md` | Выборочное чтение, поиск, ограничение вывода и diff |
| `agent-rules/environment.md` | Локальные зависимости, настройки и сервисы |
| `agent-rules/software.md` | TDD, MVP и минимальные изменения поведения |
| `agent-rules/artifacts.md` | Документы, исследования, данные и графика |
| `agent-rules/verification.md` | Тихие проверки, аудит причин и приёмка |
| `agent-rules/coordination.md` | Выбор способа работы, назначения и условный исполнитель решений |
| `agent-rules/learning.md` | Ретроспектива, аудит инструкций и сохранение решений |

## Установка в новый проект

Для копирования шаблона достаточно обычных файловых команд. Git нужен для получения и обновления этого репозитория. Сам проект может быть без Git. Новые библиотеки и глобальные пакеты не нужны.

Если репозиторий ещё не клонирован, выполните:

```sh
git clone https://github.com/Rattlhead/codex-agent-skills.git
cd codex-agent-skills
```

Если клон уже есть, перейдите в его корневой каталог.

Создайте каталог проекта, если его ещё нет. В команде ниже замените путь в `project_dir` на абсолютный путь к этому каталогу. Установка остановится, если там уже есть `AGENTS.md`, `AGENTS.override.md` или `agent-rules`, включая символические ссылки. Сначала сохраните и сопоставьте существующие инструкции; не удаляйте их ради установки.

```sh
(
set -eu
project_dir="/absolute/path/to/project"
template_dir="$PWD/templates/universal-project"
test -d "$project_dir"
test -f "$template_dir/AGENTS.md"
test -d "$template_dir/agent-rules"
for name in AGENTS.md AGENTS.override.md agent-rules; do
  if [ -e "$project_dir/$name" ] || [ -L "$project_dir/$name" ]; then
    echo "Уже существует: $project_dir/$name — установка остановлена" >&2
    exit 1
  fi
done
cp -R "$template_dir/agent-rules" "$project_dir/agent-rules"
cp "$template_dir/AGENTS.md" "$project_dir/AGENTS.md"
echo "Шаблон установлен: $project_dir"
)
```

Проверьте маршруты и ограничения проекта. Добавляйте конкретные команды, владельцев и контракты только при необходимости. Сохраняйте их в подходящем профиле или существующей документации. Начните новый чат Codex в каталоге проекта и проверьте обнаружение инструкций. Сам запуск нового чата не гарантирует загрузку: на неё влияют рабочий каталог, overrides, конфигурация и ограничения среды.

## Проект с существующими правилами

Предложите пользователю точный diff и получите разрешение на правку инструкций. Сопоставьте существующие документы с профилями шаблона. Сохраните предметные ограничения и рабочие маршруты. Перенесите только недостающие правила. Не заменяйте существующий `AGENTS.md` целиком.

Локальные `AGENTS.md` в подкаталогах могут задавать дополнительные требования. Проверьте их при изменении маршрута. Если вы переименовали профиль, обновите ссылки на него.

## Обновление

Обновление клона само по себе не меняет правила проектов. В корне клонированного репозитория выполните:

```sh
git pull --ff-only
```

Если Git сообщает о локальных изменениях или расхождении веток, сначала разберите их. Не используйте `reset --hard` для получения шаблона.

Сначала сравните краткий список различий. Замените путь в `project_dir` на путь установленного проекта:

```sh
project_dir="/absolute/path/to/project"
template_dir="$PWD/templates/universal-project"
git diff --no-index --stat -- "$project_dir/AGENTS.md" "$template_dir/AGENTS.md"
git diff --no-index --stat -- "$project_dir/agent-rules" "$template_dir/agent-rules"
```

Выполняйте команды сравнения отдельно. Код `0` означает отсутствие различий, `1` — наличие различий. Другой код означает ошибку сравнения. Эти команды только читают файлы.

Для нужного файла прочитайте подробный diff. Например:

```sh
git diff --no-index -- "$project_dir/agent-rules/context.md" "$template_dir/agent-rules/context.md"
```

Порядок обновления:

1. Выберите изменения, нужные проекту. Покажите конкретную правку пользователю и получите подтверждение, если его ещё нет.
2. Сохраните текущую версию выбранных файлов в истории проекта или в отдельной резервной копии.
3. Внесите точные правки по diff. Сохраните локальные команды, ограничения и ссылки. Добавляйте новые профили отдельно и проверяйте их маршруты.
4. Проверьте итоговый diff и относительные ссылки. Убедитесь, что каждый профиль читается при нужном условии.
5. Начните новый чат Codex в проекте и проверьте обнаружение обновлённых инструкций.

Не копируйте весь шаблон поверх установленной версии. Не используйте `rsync --delete` для обновления правил проекта. При восстановлении верните только затронутые файлы из сохранённой версии.

## Навыки

Шаблон не включает навыки в копируемые профили. Для полного набора условных маршрутов установите семь навыков по [основному README](../README.md#установка-навыков). Навыки и шаблон устанавливаются и обновляются отдельно.

| Условие | Навык |
| --- | --- |
| Выбор модели, усилия, бюджета или способа выполнения | `task-model-router` |
| Серия содержательных этапов, большой объём контекста, недостаточная способность основной модели или явный запрос координации | `subagent-manager` |
| Сложная дорожная карта, ревью или возобновление плана | `plan-agent-work` |
| Нетривиальный выбор внутри разрешённой длительной работы | `autonomous-decision-agent` |
| Связанные симптомы, повторный сбой или аудит области | `root-cause-audit` |
| Завершение крупной задачи или запрос разбора лишней работы | `task-token-retrospective` |
| Аудит инструкций или ревью их изменений | `agent-instructions-audit` |

Менеджеру обязателен роутер. Для исполнителя решений нужны оба навыка и доступный инструмент субагентов. Остальные связи условные. Базовую короткую работу можно выполнить без навыков, если её маршрут не требует отсутствующей возможности. Если обязательная зависимость недоступна, агент сообщает об ограничении и продолжает только независимую разрешённую работу.

Агент ищет навык по имени в доступном каталоге среды и читает его фактический `SKILL.md`. Не добавляйте в проект пути вида `../../skills/...`: после копирования они могут вести не туда. Каталог навыков должен быть доступен среде Codex. Установка файлов не гарантирует доступность инструментов или автоматическое применение навыка.

Не загружайте все семь навыков и все их справки заранее. Читайте только материалы текущего маршрута. Цены, алгоритм выбора и процедура координации остаются в навыках. Актуальный текст не нужно перечитывать на каждом шаге.

## Примеры маршрутов

- Небольшая правка кода: задача и контекст → разработка → затронутая проверка. Основной агент выполняет короткую задачу целиком при достаточных способностях и ограниченном контексте. Число команд само по себе не требует менеджера. Сохраняется исключение из TDD для несоразмерной или невозможной предварительной проверки.
- Обновление документа: задача и контекст → артефакты → сверка содержания и структуры. Для запроса «составь дорожную карту» применяется `plan-agent-work` в режиме плана; реализация и её проверки не запускаются.
- Серия графических материалов: задача и контекст → координация → артефакты; сначала размеры и образец, затем нужные экспорты и просмотр. Менеджер применяет обязательное делегирование по способности и для защиты контекста до полного исследования. Связанную цепочку может выполнить один исполнитель. Для неразрешённого нетривиального выбора внутри имеющихся полномочий менеджер подключает исполнителя решений.
- Повторные сбои и связанные симптомы: задача и контекст → проверки → `root-cause-audit`. Агент фиксирует область, версию, альтернативы и пробелы покрытия. Аудит не разрешает исправления. Ретроспектива затрат или аудит инструкций нужны лишь для отдельного подтверждённого вопроса.

## Проверка после адаптации

- Точные подсчёты и фильтрация выполняются доступными инструментами без передачи всего набора в контекст.
- Объединение запросов сохраняет ошибки и не расширяет область чтения.
- После сокращения контекста агент продолжает из текущего состояния и проверяет изменяемые данные по необходимости.
- Несколько действий внутри одной небольшой правки не запускают менеджера и роутер без явного запроса.
- Для правки текста агент не исследует стек без причины.
- Для известного программного поведения он может сочетать TDD с объёмом MVP.
- Для работы со средой он использует локальные зависимости и обосновывает глобальное исключение.
- При отказе тихой проверки сохраняются ошибка и код завершения.
- Агент другой области получает новое задание как новый исполнитель.
- Проверенное решение доступно по маршруту и содержит условия повторного применения.

Это проверка соответствия базы задаче. Она не требует создавать автоматические тесты для каждого документа. Русский текст использует принципы ясного технического языка; он не заявлен как соответствующий английскому стандарту ASD-STE100.

Источники рекомендаций и границы применения приведены в [справке по экономии токенов](token-efficiency.md). Справка предназначена для сопровождения шаблона. Она не входит в копируемые профили и не добавляет обязательное чтение для каждой задачи.
