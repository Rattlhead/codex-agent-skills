# Проверка исправленных правил

`cases.json` содержит 18 случаев: 10 для тарифов, 4 для продолжения работы субагента и 4 для сокращённых правил аудита.

Отдельный проверяющий `6.1 Sol / medium` получает инструкции и случаи без поля `expected`. Он выбирает решение из общего словаря без связи решений с номерами случаев. Наблюдения сохраняются в `results.json`. Главный агент проверяет объяснения и сравнивает решения с ожиданиями.

```sh
python3 tests/skill-rule-regressions/check_results.py
```

Команда сравнивает сохранённые наблюдения. Она не запускает модель и не выполняет новый аудит. Хеши четырёх проверенных исходников должны совпасть. После изменения этих файлов нужна новая оценка затронутых случаев.

Проверка покрывает частичное обновление цен, отдельные даты множителей, границу 30 дней, недатированные группы и повторное использование проверки. Она также покрывает продолжение прежнего среза после изменения версии, смену области, независимый обзор и ограничения инструмента. Случаи аудита проверяют допустимые уточнения, приоритет инструкций, сетевую неопределённость и повторную проверку изменённых данных.

Это статический разбор правил. Он не доказывает поведение всех моделей и не проверяет актуальные числовые тарифы. Новые зависимости не требуются. Материалы остаются вне устанавливаемых навыков.

Рекомендуемая модель для создания или изменения этих проверок: `6.1 Sol / medium`.
