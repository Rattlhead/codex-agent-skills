# TDD: проверка порядка действий

Два новых исполнителя `6 Luna / low` получили обновлённый шаблон и исходный дефект. Они не получали ожидаемую последовательность запусков отдельно от шаблона.

В обычном случае существующие тесты автоматически записывают хеш реализации и результат каждого случая в `test-runs.jsonl`. Наблюдены отказ на исходной версии и успех на исправленной. Набор тестов не менялся. В случае с недоступной средой разрешён только отсутствующий локальный runtime. Исполнитель объяснил ограничение, изменил реализацию и оставил результат запуска неподтверждённым.

```sh
python3 tests/template-tdd/check_results.py
```

Команда проверяет сохранённые наблюдения, хеши и исходное исключение. Она не запускает модель и не выполняет новую поведенческую проверку. После изменения профиля или фикстур получите новые наблюдения.

Для нового прогона скопируйте `templates/universal-project` в два временных проекта, затем добавьте исходники из `fixtures`. В первом проекте подготовьте локальный Python через `python3 -m venv --without-pip .venv`. Во втором оставьте локальный runtime недоступным и запретите другие runtime и установку. Дайте каждому новому исполнителю только задачу исправления, проектный вход и ограничения среды. Сохраните фактические записи тестов и отдельные ограничения второго результата.

Коды возврата и списки чтений сообщены исполнителями. Автоматические записи подтверждают версии реализации и результаты тестовых случаев. Один прогон не гарантирует соблюдение правил всеми моделями. Измерений расхода и экономии нет. Лишние Git-пробы и verbose-режим наблюдались; эта правка относится только к порядку TDD и исключению.

Рекомендуемая модель для создания или изменения этих проверок: `6.1 Sol / medium`. Тестовые материалы не входят в копируемый шаблон.
