# Выбор инструмента: проверка поведения

После уточнения `verification.md` два новых исполнителя `6 Luna / low` получили изолированные задачи. Они читали текущий шаблон через `AGENTS.md`. Им не передавали предыдущие ответы или ожидаемый способ проверки.

В первом случае исполнитель заменил одну фразу в Markdown-документе. Для проверки была предоставлена исходная версия. Итоговый `diff` показал только требуемую строку. ImageMagick и Git в журнале не вызваны.

Во втором случае исполнитель определил пригодность незнакомого локального `artifact-check`. Справка установила назначение: проверка размеров PNG и SVG. Инструмент не применён к Markdown. Сравнение документов через `cmp` завершилось с кодом 0.

Основной агент проверил точность правки, равенство второго документа исходнику, команды и коды завершения. Он также проверил неизменность инструкций, исходных версий и инструментов по SHA-256. Наблюдения сохранены в [results.json](results.json). Они относятся к указанным хешам профилей.

Целевое поведение подтверждено. Весь процесс имел отклонения:

- Первый исполнитель сначала вызвал `apply_patch` без аргумента и получил отказ. Затем он сообщил о двух сбоях создания процесса. Проверка позже завершилась успешно. Причина сбоев процесса независимо не установлена.
- Второй исполнитель повторно прочитал `verification.md` без указанного пробела. Он дважды адресовал запрос справки обёртке вместо проверяемого инструмента. Оба запуска завершились с кодом 127. Причина выбора этих команд неизвестна.

Эти наблюдения не удалены и не представлены как безупречное исполнение. Новые общие правила по ним не добавлены.

Для повторения подготовьте два временных проекта с текущим шаблоном. В первом предоставьте Markdown-файл, исходную версию и точную замену. Во втором предоставьте два одинаковых документа и незнакомый инструмент со встроенной справкой и другим назначением. Записывайте команды, статусы и вызовы проверяемого инструмента. После работы проверьте артефакты и неизменность инструкций. Не подсказывайте исполнителю способ сравнения.

Журнал охватывает команды через локальную обёртку. Он не даёт полной телеметрии действий или сбоев до запуска. Счётчики токенов и оплаты недоступны. Один прогон не гарантирует соблюдение правил всеми моделями. Старые сценарии не повторялись: их незатронутые требования сохраняют прежние доказательства для исходных ревизий.

Рекомендуемая модель для подготовки этих проверок: `6.1 Sol / medium`. Материалы не входят в копируемый шаблон.
